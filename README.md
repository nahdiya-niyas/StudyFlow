# StudyFlow – Student Productivity Platform

StudyFlow is a web-based student productivity application designed to help students organise academic activities, manage tasks, take notes and track study sessions.

The project also demonstrates practical DevOps practices through Docker, Docker Compose, Docker Hub, Kubernetes and GitHub Actions.

## Features

- User registration and authentication
- Personalised student dashboard
- Create, edit and delete notes
- Task management
- Study planner with countdown timer
- Study session tracking
- User profile management

## Technology Stack

| Category | Technologies |
|---|---|
| Backend | Python, Flask |
| Database | SQLite |
| Frontend | HTML, CSS, JavaScript |
| Containerisation | Docker |
| Container Orchestration | Kubernetes |
| CI/CD | GitHub Actions |

## Running with Docker Compose

StudyFlow can be launched using Docker Compose without manually installing Python dependencies or building the application from source.

### Prerequisites

- Docker Desktop installed and running
- Git installed

### 1. Clone the repository

```bash
git clone https://github.com/nahdiya-niyas/StudyFlow.git
cd StudyFlow
```

### 2. Configure environment variables

Create your environment file using the provided template.

**Windows CMD:**

```cmd
copy .env.example .env
```

**Linux / macOS:**

```bash
cp .env.example .env
```

Open `.env` and configure the values:

```env
SECRET_KEY=your-own-random-secret
APP_PORT=5000
```

**Environment variables:**

| Variable | Description |
|---|---|
| `SECRET_KEY` | A unique secret key generated by the user. |
| `APP_PORT` | The host port used to access StudyFlow. Defaults to `5000`. |

**Port configuration**

If port `5000` is already in use, change `APP_PORT` to an available port.

For example:

```env
APP_PORT=5001
```

The internal application port remains `5000`. Only the host port changes.

### 3. Start the application

```bash
docker compose up -d
```

Docker Compose automatically pulls the published Docker Hub image, creates the container and configures persistent database storage.

### 4. Access StudyFlow

Open your browser:

`http://localhost:5000`

If you configured a different `APP_PORT`, use that port instead.

For example, with `APP_PORT=5001`:

`http://localhost:5001`

### 5. Stop the application

```bash
docker compose down
```

The named Docker volume preserves the SQLite database when the container is removed.

To remove the application and its persistent database volume:

```bash
docker compose down -v
```

**Warning:** Removing the volume permanently deletes the stored database and user data.

## CI/CD Pipeline – GitHub Actions

StudyFlow uses GitHub Actions to automate application validation, Docker image building and publishing.

### Workflow Triggers

- Pushes to the `main` branch
- Pull requests targeting the `main` branch
- Manual workflow execution

### Pipeline Steps

1. Check out the repository.
2. Set up Python.
3. Install project dependencies.
4. Validate Python syntax.
5. Set up Docker Buildx.
6. Authenticate with Docker Hub.
7. Build the Docker image.
8. Publish the image to Docker Hub when changes are pushed to `main`.

The pipeline publishes two image tags:

- `latest`
- Git commit SHA

Pull requests and manual workflow executions build the image without publishing it.

### GitHub Actions Secrets

The following repository secrets are configured:

| Secret | Purpose |
|---|---|
| `DOCKERHUB_USERNAME` | Docker Hub username |
| `DOCKERHUB_TOKEN` | Docker Hub access token |

Credentials are stored securely using GitHub repository secrets.

## Kubernetes

Kubernetes deployment manifests are maintained in the project's `kubernetes/` directory.

These manifests provide configuration for deploying and managing StudyFlow in a Kubernetes cluster.

A running Kubernetes cluster is required before deployment.

Any required Kubernetes Secrets must be created separately in the cluster. The local `.env` file is not automatically transferred to Kubernetes.

## Security

- Actual environment files are excluded from version control.
- `.env.example` provides a template without exposing real credentials.
- Docker Hub authentication uses GitHub Actions repository secrets.
- Users should generate their own secret key.
- Never commit or share your actual `.env` file.
