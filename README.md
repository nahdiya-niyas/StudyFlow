# StudyFlow – Student Productivity Platform

StudyFlow is a web-based student productivity application designed to help students organise their academic activities, manage tasks, take notes and track their study sessions.

The project also demonstrates containerisation and DevOps practices through Docker, Docker Hub and GitHub Actions.

## Features

- User registration and authentication
- Personalised student dashboard
- Create, edit and delete notes
- Task management
- Study planner with countdown timer
- Study session tracking
- User profile management

## Run with Docker Compose

StudyFlow can be launched using Docker Compose without manually installing Python dependencies or configuring the application source code.

### Prerequisites

- Docker Desktop installed and running
- Git installed

### 1. Clone the repository

```bash
git clone https://github.com/nahdiya-niyas/StudyFlow.git
cd StudyFlow
```

### 2. Configure environment variables

Create your own environment file from the example:

```bash
copy .env.example .env
```

Open `.env` and configure the variables:

```env
SECRET_KEY=your-own-random-secret
APP_PORT=5000
```

**Configuration:**

- `SECRET_KEY`: A unique secret key generated by the user.
- `APP_PORT`: The port used to access StudyFlow on the host machine.

**Port configuration:** If port `5000` is already occupied, change `APP_PORT` to another available port, such as `5001` or `5002`.

For example:

```env
APP_PORT=5001
```

The internal application port remains `5000`. Only the host port is configurable.

### 3. Start StudyFlow

```bash
docker compose up -d
```

Docker Compose automatically pulls the published image from Docker Hub, creates the container and configures persistent storage.

### 4. Access the application

Open your browser:

```text
http://localhost:5000
```

If you configured a different `APP_PORT`, use that port instead.

For example:

```text
http://localhost:5001
```

### 5. Stop StudyFlow

```bash
docker compose down
```

The named Docker volume preserves the SQLite database when the container is stopped or removed.

To remove the application and its persistent database volume:

```bash
docker compose down -v
```

**Warning:** Removing the volume permanently deletes the database stored in it.

## CI/CD Pipeline – GitHub Actions

StudyFlow uses GitHub Actions to automate the build and publishing process.

The workflow is triggered by:

- Pushes to the `main` branch
- Pull requests targeting the `main` branch
- Manual workflow execution

### Pipeline Workflow

1. Check out the repository.
2. Set up Python.
3. Install project dependencies.
4. Validate Python syntax.
5. Set up Docker Buildx.
6. Authenticate with Docker Hub using GitHub repository secrets.
7. Build the Docker image.
8. Push the image to Docker Hub when changes are pushed to `main`.

The pipeline publishes two image tags:

- `latest`
- Git commit SHA

Pull requests and manual workflow executions build the image without publishing it.

### GitHub Actions Secrets

The following repository secrets are configured:

| Secret | Purpose |
|---|---|
| `DOCKERHUB_USERNAME` | Docker Hub username |
| `DOCKERHUB_TOKEN` | Docker Hub access token |

The Docker Hub token is stored securely as a GitHub Actions secret rather than directly in the workflow file.

## Kubernetes

Kubernetes configuration files are maintained in the project's `kubernetes/` directory.

These manifests are intended for deploying and managing StudyFlow in a Kubernetes cluster.

A running Kubernetes cluster is required before applying the configuration.

If using the Kubernetes manifests, configure the required Kubernetes Secret in your cluster separately. The application's local `.env` file is not automatically transferred to Kubernetes.

## Security

- Sensitive environment variables are excluded from version control.
- `.env.example` provides a configuration template without exposing actual secrets.
- Docker Hub authentication uses GitHub Actions repository secrets.
- Users should generate their own secret key when running the application.

**Never commit your actual `.env` file or expose your secret keys.**
